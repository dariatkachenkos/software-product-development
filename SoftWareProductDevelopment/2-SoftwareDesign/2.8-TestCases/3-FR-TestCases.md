# Тестові сценарії функціональних вимог

**Метод, що тестується:** `NutritionTracker.getDailyCalories(date: Date): number`

**Опис:** Метод повертає загальну кількість калорій денного раціону музиканта за вказану дату.

## BlackBox-тести (FR1.2)

| ID | Тест | Вхідні дані | Очікуваний результат | Вимога |
|----|------|-------------|----------------------|--------|
| TC-BB-01 | Розрахунок калорій при наявності записів | date = 2026-05-10; записи: 200г курятини (165 ккал/100г), 150г рису (130 ккал/100г) | 330 + 195 = **525 ккал** | FR1.2 |
| TC-BB-02 | Розрахунок при відсутності записів | date = 2026-05-10; записів немає | **0 ккал** | FR1.2 |
| TC-BB-03 | Розрахунок при некоректній даті (null) | date = null | **Помилка: InvalidDateError** | FR1.2 |
| TC-BB-04 | Розрахунок при майбутній даті | date = 2099-01-01 | **0 ккал** або **FutureDateError** | FR1.2 |

## WhiteBox-тести (покриття операторів)

```javascript
// Алгоритм getDailyCalories(date):
// 1. Перевірити date != null
// 2. Знайти DailyIntake за (musicianId, date)
// 3. Якщо не знайдено → повернути 0
// 4. Для кожного FoodEntry: sum += entry.calculateCalories()
// 5. Повернути sum
```

| ID | Тест | Мета покриття | Вхідні дані | Очікуваний результат |
|----|------|--------------|-------------|----------------------|
| TC-WB-01 | Покриття оператора перевірки null | Оператор 1 | date = null | InvalidDateError |
| TC-WB-02 | Покриття гілки «запис не знайдено» | Оператори 2,3 | date = 2026-01-01, записів немає | 0 |
| TC-WB-03 | Покриття циклу обходу записів | Оператори 4,5 | date = 2026-05-10, 2 записи | Сума калорій |
